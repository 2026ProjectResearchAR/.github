# 要件定義書

## 1. システム概要
本プロジェクトは、専用アプリケーションのインストールを不要とする「Web ARアプリケーションの開発」と、学内のリアルタイムデータを収集する「IoTセンサーネットワークの構築」を融合させたシステムである。
キャンパス内での快適な移動、イベント性の提供（スタンプラリー）、および災害時の安全確保（避難シミュレーション）を一元的に実現し、食堂や自習室の混雑状況を予測・可視化して学生の利便性を向上させることを目的とする。

---

## 2. 開発手法・アプローチ
開発は以下の3つのフェーズ（段階）に分けて段階的に進行する。

### 第1段階：基盤整備およびマップ解析
* **AR描画環境の構築**: Webブラウザ上で動作するAR空間において、3Dオブジェクトを安定して表示・描画するフロントエンド環境を整備する。
* **3Dマップ自動生成ロジックの構築**: キャンパスの既存2Dマップデータを解析し、自動的に3Dマップデータを生成するロジックを開発。AR体験を途切れさせないための空間認識の補助基盤として活用する。

### 第2段階：機能実装およびIoTネットワーク構築
* **AR機能の実装**: 精査された施設情報を基に、AR上での最適な表現技法を実装する。これには「災害時の避難シミュレーション機能」や「スタンプラリー機能」が含まれる。
* **IoTセンサーの設置**: 食堂や自習室などの学内各スポットに、プライバシーに配慮した環境センサー群を設置する。
* **バックエンドシステムの構築**: センサーから取得したデータをサーバーへリアルタイムに集約し、混雑状況の需要予測を行うデータ解析基盤およびAPIを構築する。

### 第3段階：統合テストおよび実運用移行
* **現地設置**: 実際のキャンパス内にARマーカーおよびIoTデバイスを設置する。
* **統合テストの実施**: 現地における通信状況の確認、ARマーカーの認識精度検証、各センサーの動作確認を行い、バグを排除した上で実運用へと移行する。

## 3. 機能要件

### 3.1 フロントエンド（Web ARアプリケーション）
| 項番 | 機能名 | 機能概要 |
| :--- | :--- | :--- |
| FE-01 | 専用アプリ不要のWeb実行 | ユーザーが専用アプリをインストールすることなく、Webブラウザから即座にアクセス・利用可能とする。 |
| FE-02 | AR 3Dオブジェクト描画 | AR空間上に対象の3Dオブジェクトを正確に配置・描画する。 |
| FE-03 | 2D→3Dマップ自動生成 | 既存の2Dキャンパスマップを解析し、空間認識を補助するための3Dマップデータを自動生成する。 |
| FE-04 | 避難シミュレーション | 災害時、AR空間上に安全な避難経路や施設情報を可視化・誘導する。 |
| FE-05 | スタンプラリー機能 | 学内回遊を促すためのARスタンプラリー機能を実装する。 |
| FE-06 | リアルタイム混雑度可視化 | バックエンドから取得した食堂・自習室の混雑度および需要予測データを、UI上に分かりやすく表示する。 |

### 3.2 バックエンド・IoTシステム
| 項番 | 機能名 | 機能概要 |
| :--- | :--- | :--- |
| BE-01 | IoTデータ収集 | 学内各スポットに設置された環境センサー群から、リアルタイムに混雑状況データを受信する。 |
| BE-02 | プライバシー配慮データ処理 | カメラ画像等の個人特定につながる情報は使用せず、環境センサー（人感、CO2、音など）を用いてプライバシーに配慮したデータ処理を行う。 |
| BE-03 | データ集約・蓄積 | センサーから送られてくる時系列データをサーバー側で効率的に集約・保存する。 |
| BE-04 | 混雑需要予測ロジック | 蓄積されたデータを基に、食堂や自習室の今後の混雑状況を予測するアルゴリズムを構築する。 |
| BE-05 | データ提供API | フロントエンド（Web AR側）へ予測データおよびリアルタイムデータを届けるためのAPIを構築する。 |

## 4. 非機能要件

### 4.1 パフォーマンス・信頼性
* **空間認識の補助**: 2Dマップから生成した3Dデータを補助基盤とすることで、現地でのAR体験が途切れない安定性を確保する。
* **通信最適化**: 現地の通信状況（Wi-Fiやキャリア回線）に左右されにくいよう、3Dオブジェクトのデータ軽量化やキャッシュ機構を検討する。

### 4.2 セキュリティ・プライバシー
* **プライバシーの保護**: 設置するセンサー群は、個人の行動や顔を特定しない環境センサー（またはプライバシーに配慮した組み込みマイコン側の処理）に限定する。

### 4.3 運用・テスト要件
* **マーカー認識精度**: キャンパス内の環境（光の当たり方、時間帯など）に応じたARマーカーの認識精度を現地で検証し、誤認識を最小限に抑える。
* **ハードウェアの堅牢性**: 学内に設置するマイコンおよび環境センサー群が、安定して連続稼働できる電源・配置環境を確保する。

## 6. チーム開発における分担イメージ（参考）
* **フロントエンド班**: React/Next.jsを用いたUI構築、AR描画環境の整備、避難シミュレーション・スタンプラリー等の画面実装。
* **アルゴリズム・マップ班**: 2Dマップの解析および3Dマップデータ自動生成ロジックの開発。
* **IoT・バックエンド班**: 組み込みマイコン・センサーの制御、データ集約サーバーの構築、需要予測アルゴリズムの実装、API開発。
* **現地統合テスト班（全員）**: マーカー・デバイスの設置、現地通信テスト、デバッグ、実運用移行手続き。
